# Проверка надёжности, 14 октября 2026

Проверка без рабочего прогона, живых сервисов и запуска браузеров:
107 тестов прошли, 4 теста с браузером исключены. Использовались fake clock,
подменённые API, процессы и browser context. Это проверка логики отказов;
живой поиск и поведение на другой ОС здесь не подтверждались.

## Найдено и исправлено

- CLI и CapGuru принимали `inf`/`nan` в таймерах. Теперь такие значения
  отклоняются до получения заданий или запуска браузера.
- Ошибка создания файла ключа оставляла временную конфигурацию прокси.
  Очистка теперь выполняется даже при неполной подготовке пакета.
- Родитель мог ждать первый бесконечно работающий worker, не замечая аварии
  другого. Неожиданное завершение worker теперь останавливает остальные
  и выдаёт ошибку. Обычные ошибки отдельного цикла по-прежнему обрабатываются
  внутри worker и не останавливают пул.
- Зависший дочерний runner мог удерживать прокси навсегда. Добавлен watchdog:
  число заданий в chunk × (deadline + 90 секунд) + 180 секунд на запуск/закрытие.
  После превышения границы процесс завершается, задания остаются на диске,
  прокси возвращается в очередь. Автоматического переотправления отчёта нет.
- Ошибка закрытия браузера блокировала отправку уже полученных результатов.
  При такой ошибке допустимые результаты отправляются один раз, а ошибка
  закрытия отдельно сохраняется. Ошибка самой отправки не вызывает повтор.
- Ошибка сохранения метаданных CapGuru прерывала закрытие клиентов.
  Теперь она фиксируется предупреждением; очистка продолжается.

Регрессионные проверки CAPTCHA подтверждают автоматический возврат к флажку,
отсутствие ручного ожидания, обновление после отказа/тайм-аута, опрос того же ID
и отсутствие повторного создания задачи при неизвестном результате отправки.

## Осталось для дальнейшей проверки

- Получение задач родителем использует Requests с connect/read timeout.
  Эти ограничения не являются абсолютным сроком для всего HTTP-ответа:
  медленно поступающий ответ теоретически может удерживать поток дольше.
  Watchdog дочернего браузерного процесса не покрывает родительский fetch.
- Остановка дерева процессов на Windows использует taskkill. В этой проверке
  реальная Windows-среда не использовалась.
- Селекторы и типы CAPTCHA, фактический результат распознавания, HTTP 429
  и сохранение записи в prstar требуют отдельных наблюдений на сервере.
  Неизвестная разметка и ошибки не должны отправляться как «Not found».
