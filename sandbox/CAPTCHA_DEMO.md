# Демо SmartCaptcha — 13 октября 2026

Страница: https://captcha-api.yandex.ru/demo
Осмотр выполнен в Codex In-app Browser, язык виджета английский.
Пользователь сам открыл задание и прошёл текстовую CAPTCHA.
Решатель CapGuru не вызывался; ответ/токен CAPTCHA не считывались и не сохранялись.

## Наблюдаемая структура

В главной странице форма Name/Submit и отдельные iframe SmartCaptcha.
Текстовая CAPTCHA находится в iframe[title="SmartCaptcha advanced"].
Флажок находится в другом iframe[title="SmartCaptcha checkbox"].
Поиск элементов только в основной странице здесь не сработает.

| Элемент | Подтверждённый селектор внутри advanced iframe |
|---|---|
| Картинка | .AdvancedCaptcha-View img (одна, 248×82 CSS px в этом показе) |
| Контейнер картинки | .AdvancedCaptcha-View |
| Поле ответа | .Textinput input.Textinput-Control |
| Кнопка ответа | .CaptchaButton_view_action |
| Контейнер задания | .AdvancedCaptcha |

Старые классы Textinput, AdvancedCaptcha-View, AdvancedCaptcha и
CaptchaButton_view_action сохранились. Но старый check_captcha ищет их
без переключения iframe и проверяет заголовок «Вы не робот?». Заголовок
страницы демо — Yandex SmartCaptcha Demo. Поэтому старую функцию нельзя
неизменённой запускать на демо, даже при совпадении внутренних классов.

Названия файлов iframe включают язык и хеш версии. Их не следует фиксировать
целиком в селекторе. Проверенные title подходят для этой версии демо;
другие варианты ещё должны подтверждаться наблюдением.

## Подтверждение результата — зависит от сценария

Демо: пользователь прошёл задание. В checkbox iframe у #js-button
aria-checked изменился с false на true. Свойство native checked осталось false.
Проверка успеха для этого демо — видимый #js-button[aria-checked="true"],
а не :checked и не смена заголовка основной страницы.
Наличие скрытого input[name="smart-token"] наблюдалось, его значение не читалось.
Общая кнопка Submit самой демо-формы не нажималась.

Поиск Яндекса: этот критерий автоматически переносить нельзя. Нужны
признаки возвращения в правильную выдачу, совпадение запроса, загрузка новых
результатов и проверка HTTP/страницы блокировки. Исчезновение CAPTCHA или
готовый ответ сервиса не означают, что поиск доступен: возможен HTTP 429.
Отдельно должна распознаваться достоверная пустая выдача.

В ранее сохранённых page.html поиска найдены CheckboxCaptcha-Button в основной
странице без iframe. Подтверждённого сохранённого DOM текстового задания поиска
для сравнения всех внутренних элементов пока нет. Демо подтверждает один
актуальный вариант SmartCaptcha, но не все варианты защиты поиска.

## Изменение и проверка адаптера

Challenge получил необязательные frame_selector и success_frame_selector.
Текущая страница остаётся вариантом по умолчанию. Перед вызовом решателя
проверяется однозначность каждого указанного iframe. Несколько одинаковых
фреймов приводят к отказу без отправки картинки.

Добавлены два локальных сценария: успех с заданием и подтверждением в разных
iframe, отказ при дублировании challenge iframe. Ответ решателя поддельный,
интернет отключён. CAPTCHA-модули: **32 passed in 10.67s**.

Адаптер не подключён к живому runner и не решал демо автоматически.
Следующий этап: зафиксировать актуальную текстовую CAPTCHA реального поиска
до/после ручного прохождения и задать для неё собственный критерий успеха.
