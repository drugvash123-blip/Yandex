# Первичный обзор — 12 октября 2026

## Вывод по стеку

Для браузерных сценариев рекомендую сохранить Python и постепенно перейти на
Playwright. Автоожидания действий, независимые browser contexts, стандартная
эмуляция устройств и трассировки сокращают количество самодельного кода.
Миграция не исправляет неверные условия, бесконечные циклы и ошибки статистики.
Selenium остаётся пригодным для начальной проверки существующего проекта;
Selenium Manager устраняет необходимость хранить фиксированный драйвер в Git.

Если цель — получать выдачу и позиции, сначала оценить Yandex Search API.
API не заменяет сценарий перехода в браузере; совпадение с персонализированной
выдачей браузера нужно проверять отдельно.

Минимальная архитектура: Python 3.11+, Playwright для браузера, один HTTP-клиент
с таймаутами, dataclass для задачи/результата, logging, pytest, JSONL либо SQLite
для результатов. Начать с последовательного конечного runner; после проверки —
asyncio и Semaphore для ограниченной параллельности. Docker/очередь/Redis сейчас
не обязательны. Использовать согласованный профиль браузера, а не случайный
User-Agent Firefox/Safari поверх Chrome. CAPTCHA выделить в отдельное состояние
с ограниченным временем и диагностикой.

## Дефекты и порядок исправлений

1. main.py запускает бесконечный цикл при импорте; vars.py читает argv и ключ
   при импорте. Нет явной конфигурации и валидации отсутствующего proxy.txt,
   числа worker и формата прокси/заданий. Нужны main guard и конечный runner.
2. thread_count и usedIPs изменяются без блокировки. Проверка лимита происходит
   после запуска потока. Ошибка до завершения createBot оставляет счётчик/IP,
   driver.quit и удаление профиля не гарантированы. Нужен finally и пул задач.
3. Bot.stats — изменяемый атрибут класса. res_task сбрасывает его только после
   успешного чтения ответа, без проверки HTTP-статуса. Данные могут смешиваться
   между ботами или теряться после неуспешной отправки.
4. check_page принимает совпадение подстроки отображаемого текста как домен.
   Нужны нормализация hostname из URL, точное сравнение и явная политика поддоменов.
   Клик подавляет исключения, поэтому найденный результат не означает переход.
5. При переходе на вторую страницу search записывает page=1. Для «Показать ещё»
   DOM может содержать накопленные результаты — позиция требует другой модели.
6. scrollToElement вычисляет отрицательные steps, затем range(0, steps) пуст.
   В mobile_scroll нужны целочисленные координаты и отдельно проверенная
   модель touch input: по умолчанию ActionChains не настраивает touch-устройство.
7. В поиске и CAPTCHA есть неограниченные циклы/рекурсия. requests и HTTPSConnection
   не имеют явных таймаутов; ответы CAPTCHA разбираются split без проверки формата.
   Нужны общий deadline, предел попыток, обработка HTTP-ошибок и закрытие соединений.
8. В ветке neterror условие len(window_handles)>0 закрывает даже последнее окно.
   current_window всегда оставляет первое окно, что не гарантирует нужную страницу.
9. Профиль уникален по IP+порту, расширение — только по IP: прокси с одним хостом
   и разными учётными данными могут перезаписывать общий background.js.
10. Ключи в исходниках/данных, proxy credentials в логах. Очистка текущего лога
    не удаляет его из старых коммитов. Для дальнейших запусков вынести секреты
    в окружение и маскировать учётные данные в логировании.

## План прогонов

1. Offline регрессии существующих методов — запускаются сейчас.
2. Локальный browser smoke исходных обёрток — подготовлен отдельно.
3. После исправлений: одна задача на Яндексе, один браузер, без параллельности,
   фиксированная конфигурация, скриншот/HTML при ошибке и deadline.
4. Только после успешного одиночного прогона — несколько повторений и проверка
   изоляции двух worker. Работоспособность внешних сервисов проверять отдельно.
