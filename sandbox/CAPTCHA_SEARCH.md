Это подтверждает общий набор классов со старым кодом и демо, но другой тип
задания и другую область поиска элементов. Не следует использовать правила
текстового демо автоматически для задачи с силуэтами.

## Захват и безопасность кликов

Первый снимок advanced-формы был сделан до загрузки картинок и оказался пустым.
Полностью отрисованная задача сохранилась в конечном page.png.
Исправлен наблюдатель: учитываются complete/naturalWidth/naturalHeight и хеш
источника изображения. Смена загрузки или изображения создаёт новую запись.
Полный URL источника в структурный JSON не записывается. HTML/снимки по-прежнему
содержат исходные данные страницы и находятся только в ignored-артефактах.

Для задачи с порядком важен образец инструкции, а не только основная картинка.
Однако область снимка не должна автоматически считаться областью кликов:
на снимке карточки могут оказаться инструкции и кнопки.
Challenge.click_area_selector задаёт отдельную разрешённую область.
Все координаты валидируются до первого клика. Хотя бы одна координата вне
картинки приводит к отказу без частичного выполнения/нажатия Submit.

Локально проверены допустимая координата и ответ с первой допустимой,
но второй выходящей в область инструкции: во втором случае нет ни одного клика.
Проверен поздно загружаемый образец изображения и отсутствие URL источника
в структурном JSON. Выборка CAPTCHA/таймаутов/наблюдения: 42 passed in 23.69s.

## Состояние после ожидания

За отведённые 15 минут CAPTCHA не была завершена; результат исходного поиска
captcha, pages_checked=0. Это ожидаемая остановка ручного наблюдения, не сбой
платного сервиса. Окно сохранено для ручной проверки, runner больше не кликает
и не листает страницы. Пользователь получил просьбу пройти задачу вручную
и сообщить, открылась ли выдача, 429 или новая CAPTCHA.
Пользователь затем прошёл последовательность заданий вручную.
inspection-network.jsonl подтверждает повторные переходы на showcaptcha,
затем HTTP 429 выдачи в 17:03:16 по Москве и HTTP 200 того же запроса
в 17:03:28 (примерно через 12,6 секунды). Пользователь подтвердил видимую выдачу.
Источник повторной навигации журналом не установлен; runner уже не управлял
страницей и не выполнял reload. Исходный result.json с captcha не изменён:
это отдельное ручное наблюдение после завершения прогона.

Следствие для автокапчи: ответ одного задания не завершает всю проверку;
следующее задание нужно отличать от неправильного ответа и готовой выдачи.
После CAPTCHA возможна промежуточная 429, поэтому проверять нужно итоговый
доступ к выдаче. Существующее пассивное ожидание runner до 120 секунд с паузой
после восстановления соответствует наблюдению, но в этом ручном эпизоде
runner автоматически не продолжал поиск. Подтверждения полного автоматического
цикла пока нет. Бюджет одной платной задачи нельзя незаметно расширять на
несколько этапов; при следующем задании требуется ручной режим или заранее
согласованный отдельный бюджет.

Параметры/качество распознавания силуэтов у CapGuru пока не проверены.
В runner добавлен необязательный async-обработчик CAPTCHA, передаваемый из Python.
CLI по умолчанию сохраняет ручной режим; обращения к CapGuru не включены.
Обработчик вызывается максимум один раз за поиск, включая сбой соединения.
Его возврат не означает успех: runner отдельно проверяет отсутствие CAPTCHA,
HTTP-ответ, запрос и настоящие результаты поиска. Новое задание или неверный
ответ оставляют ручное ожидание; автоматических повторных отправок нет.

Локальная интеграция использует настоящий captcha_browser и подставной решатель:
принятый ответ → выдача → целевой сайт; новое задание; неверный ответ;
429 → восстановление выдачи → сайт; ошибка решателя → ручной режим.
Это проверяет управление сценарием, но не качество распознавания CapGuru
и не универсальность селекторов живого Яндекса. Для живого подключения ещё
нужен адаптер конкретного типа задания и подтверждения его результата.

Проверка после интеграции: `.venv/bin/pytest sandbox -q` — 107 passed,
3 xfailed (известные дефекты неиспользуемого старого кода), 179,56 секунды.
Все пять новых сценариев проверены локально, без оплачиваемых запросов.

## Диагностика типа задания

`captcha_detection.inspect_captcha` только читает DOM всех фреймов. По ранее
наблюдавшимся классам он различает text, silhouette, checkbox, slider и unknown.
Скрытые контейнеры не учитываются. Несколько видимых контейнеров дают ambiguous;
ошибка при смене документа — changing. Отсутствие знакомого контейнера даёт
unrecognized, а не «CAPTCHA пройдена».

Для текста/силуэтов ready означает только готовность элементов: картинки
загрузились, контейнер изображения один, кнопка доступна, поле текста доступно.
Это не подтверждение поддержки платным решателем. Для остальных типов требуется
ручная проверка. Ответы, токены и адреса изображений этот модуль не собирает.
Runner сохраняет результат в `captcha-*-diagnosis.json` рядом с прежними снимками.

Локальные тесты включают основной документ, iframe, дублирующиеся задания,
скрытый флажок, незагруженное изображение и отключённое поле. Проверка связанных
модулей: 49 passed, 35 deselected, 40,95 секунды. Живые селекторы новых вариантов
и качество распознавания пока не проверены. Вызов CapGuru остаётся отключённым.

## Выбор текстового обработчика

`TextCaptchaHandler` принимает подставляемый async-решатель и явно заданный
селектор результата. Он допускает только готовое одиночное текстовое задание
в основной странице или проверенном iframe с title SmartCaptcha advanced.
Другие типы, неизвестный iframe, дублирование и незагруженные картинки
останавливают обработку до вызова решателя. Демо может подтверждать результат
в отдельном checkbox iframe; для поиска проверка runner остаётся обязательной.

Исправлены учёт скрытых iframe и ожидание нескольких возможных элементов
результата: скрытое сообщение об ошибке перед видимым успехом больше не мешает
ожиданию. Пять сценариев runner теперь используют выбор по диагностике вместо
ручного описания Challenge. Связанные тесты: 50 passed, 35 deselected, 42 секунды.
Платное подключение через CLI не включено, текстовая CAPTCHA реального поиска
с этими селекторами ещё не подтверждена.
