# CAPTCHA: разбор и первый этап рефакторинга

13 октября 2026. Живые CAPTCHA и платный API не вызывались.

## Найденные проблемы

- Legacy смешивает получение изображения, отправку платной задачи, ожидание,
  разбор ответа и действия Selenium в одной большой функции.
- wait_captcha_response ждал бесконечно, без сетевых таймаутов, и проверял
  CAPTCHA_NOT_READY вместо документированного CAPCHA_NOT_READY.
- Ответы разбирались цепочками split без проверки формата/кода ошибки.
- В ветке slider использовался другой встроенный ключ, чем в остальных ветках.
- Отправка, загрузка картинок и polling использовали HTTP и не имели таймаутов.
- В check_captcha есть рекурсия, циклы повторных кликов и возможные повторные
  платные отправки. Общего бюджета задач решателя на браузерный прогон нет.
- Координаты не проверялись относительно размера картинки; не было защиты
  от применения ответа к уже сменившейся CAPTCHA.

## Что сделано

Новый Source/bots/captcha_service.py отделяет транспорт и разбор протокола:

- явные ключ и HTTPS endpoint; создание/импорт клиента ничего не отправляет;
- одна попытка создания платной задачи на экземпляр клиента, без повторной
  отправки после неоднозначного сетевого сбоя;
- ограниченные ожидание, количество опросов и таймауты HTTP;
- JSON и текстовые ответы; поддержка обоих написаний статуса ожидания;
- ошибки сервиса, транспортные ошибки и таймауты различаются;
- неожиданное тело ответа/исключение не включается в диагностическое сообщение;
- координаты проверяются по формату и границам предоставленного изображения;
- redirects запрещены, собственная HTTP-сессия закрывается через context manager.

Совместимое legacy-ожидание timeLib.wait_captcha_response тоже ограничено,
переведено на HTTPS и использует общий разбор. Формат успешного возврата
OK|answer сохранён для старых вызывающих функций. Ошибки теперь прерывают
ожидание исключением, вместо попытки использовать ошибку как решение.
Встроенный ключ slider заменён на общую переменную key без вывода её значения.

Важно: новые ограничения сервиса не означают, что вся старая функция
check_captcha переписана. Её клики, циклы и первичные HTTP-отправки остаются
legacy-кодом. Рабочий Playwright runner её не использует.

## Локальные проверки

24 теста CAPTCHA-модуля/совместимого ожидания прошли без сети, с фиктивным
ключом и заменёнными HTTP-ответами/часами. Проверены успех, ожидание, нулевой
баланс, нерешаемая задача, мусор/невалидный JSON, неверный task ID, предел опросов,
общий deadline, сетевой сбой без повторной отправки, границы координат и HTTPS.
С legacy-набором: 27 passed, 3 xfailed. Три ожидаемых legacy-дефекта относятся
к ранее известным проблемам и не являются подтверждением готовности автокапчи.

Новый модуль пока не подключён к runner. Автоматическая отправка изображений
не включена; обычный рабочий поиск сохраняет ручное прохождение CAPTCHA.
Списание денег, баланс и работоспособность живого ключа не проверялись.

## Следующий этап без платных вызовов

Обновление: локальный Playwright-адаптер реализован в captcha_browser.py.
Он принимает явное описание элементов и подменяемую async-функцию решателя.
Тестируются текст и координаты; screenshot снимается в CSS-пикселях, включая
проверку при device_scale_factor=2. Изменение картинки/размера до применения
ответа прерывает обработку. Кнопка отправки нажимается один раз, затем требуется
явный видимый элемент успеха. Нет повторного решения/перезагрузки страницы.
Шесть локальных браузерных сценариев прошли с offline=True и фиктивным
решателем: текст, координаты, смена изображения, неверный ответ, координаты
за границей, отсутствующее поле. Вместе с сервисом: 30 passed.
Адаптер не распознаёт автоматически Яндекс и не подключён к runner;
slider остаётся неподдержанным, вместо угадывания действий.
Полный локальный набор проекта после подготовки коммита: 97 passed,
3 xfailed in 150.06s. Ожидаемые xfail относятся к сохранённым legacy-дефектам.
После осмотра демо добавлены раздельные фреймы задания и подтверждения успеха,
а также отказ при неоднозначном iframe. 32 проверки CAPTCHA-модулей прошли.
Наблюдения и различие подтверждения демо/поиска — CAPTCHA_DEMO.md.
Поиск показал задачу с силуэтами в основной странице. Её структура и доработки
захвата/области кликов описаны в CAPTCHA_SEARCH.md. Платных вызовов не было.

1. Для будущей интеграции описать актуальные варианты Яндекса: определить тип, снять только область CAPTCHA,
   запомнить идентичность задания, получить ответ через подменённый сервис.
2. Локальные страницы с текстовой CAPTCHA/координатами, изменившейся картинкой,
   исчезнувшей формой, неверным ответом и отсутствием подтверждения прохождения.
3. Ответ решателя не считать успешным прохождением: проверять состояние браузера.
4. Для неизвестного типа оставить ручной режим. Slider не переносить наугад:
   его старые параметры/алгоритм нужно отдельно подтвердить.
5. При будущей интеграции один клиент/бюджет на весь прогон, а не новый клиент
   на каждую попытку. Иначе лимит одной платной отправки теряет смысл.

## Как ограничить будущий живой тест

После проверки адаптера и отдельного согласования объёма: одна задача,
одна разрешённая отправка, без повторов/перезапуска CAPTCHA, только скриншот
самой CAPTCHA, явная стоимость и проверка баланса в кабинете. Для нескольких
этапов новой CAPTCHA остановиться и передать управление пользователю.
Успех/неуспех платного решателя не гарантирует отсутствие HTTP 429.
