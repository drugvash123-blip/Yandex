# Перенос и запуск

Нужны Python 3.11+ и установленный Google Chrome, а также рабочий стол
(окно Chrome должно быть доступно). Архив содержит исходники: отдельная
компиляция Python не требуется. Старый Selenium-worker не используется.

## Установка

Распакуйте архив и откройте терминал в папке проекта.

macOS / Linux:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.runtime.txt
```

Windows PowerShell:

```powershell
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.runtime.txt
```

В Windows в дальнейших командах заменяйте `python` на
`.venv\Scripts\python.exe`, если окружение не активировано.
ChromeDriver и `playwright install` для установленного Google Chrome не нужны.
Версии зависимостей зафиксированы по проверенной среде macOS/Python 3.11;
на другой ОС живой прогон пока не проверен.

## Локальная конфигурация

Создайте папку `Data` и файлы (они не входят в архив или Git):

- `Data/service-key.txt`: ключ prstar, одна строка.
- `Data/key.txt`: ключ CapGuru, одна строка.
- `Data/proxy.json`: параметры своего прокси:

```json
{
  "server": "socks5://PROXY_HOST:PROXY_PORT",
  "username": "PROXY_LOGIN",
  "password": "PROXY_PASSWORD"
}
```

Настоящие значения перенесите отдельно. Профиль Chrome создастся автоматически.
Для преобразования файла `n`, содержащего строки `ip:port@login:password`, выполните
`python sandbox/proxy_to_json.py n x`: в файл `x` запишется JSON-массив конфигураций.
Пустые строки пропускаются; при неверной строке выходной файл не изменяется.
Постоянный режим с workers принимает весь массив через `--proxies-file`.
Для одиночного теста runner принимает один объект через `--proxy-config`.
По умолчанию используется SOCKS5; для HTTP добавьте
`--scheme http`, для HTTPS — `--scheme https`.
Можно перенести сохранённый `Data/browser-profiles/ab-webshare-a` с закрытым
браузером на совместимую среду, но перенос cookies между ОС не гарантируется.
По умолчанию на новом компьютере начните с нового профиля.

## Постоянная работа с несколькими workers

Сохраните результат конвертера в `Data/proxies.json`:

```sh
python sandbox/proxy_to_json.py n Data/proxies.json
```

Запуск трёх параллельных workers (из корня проекта, после установки):

```sh
python Source/bots/main.py --workers 3 --proxies-file Data/proxies.json --service-key-file Data/service-key.txt --task-poll-interval 1 --client-id worker-transfer --profiles Data/browser-profiles/workers --headed --captcha-key-file Data/key.txt --captcha-max-tasks 0 --captcha-kinds both --captcha-wait 900 --deadline 1800 --max-pages 5 --action-pause 15 --visit-seconds 100 --output sandbox/artifacts/workers
```

Workers постоянно перебирают прокси по очереди и получают задания prstar.
Каждый worker имеет собственный HTTP-клиент. На одном прокси одновременно
работает только один worker; его профиль сохраняется между пакетами.
Количество активных workers не превышает количества прокси. Задания каждого
пакета выполняются последовательно в отдельном процессе с браузером;
разные workers работают параллельно. Пустой ответ не открывает браузер.
После пакета или ошибки worker ждёт секунду и переходит к следующему прокси.
Прямое получение задач prstar сохраняет исходный протокол; прокси используется
браузером для поиска и посещения сайтов.

Ctrl+C останавливает все workers и их браузерные процессы. Полученные задания
и результаты сохраняются, но автоматического повтора незавершённых заданий
после остановки нет. Пакеты с ошибками также не отправляются повторно вслепую.
`workers.log` — общий журнал; в папках `worker-N/пакет/chunk-N` находятся логи,
результаты и квитанции каждого браузерного запуска. Временные файлы ключа и
прокси удаляются после запуска; после аварийного завершения ОС могут остаться
в папке логов. Не публикуйте эту папку.

## Один тестовый цикл с заданиями prstar

Следующая команда подходит для обеих ОС: выполните её одной строкой.

```sh
python Source/bots/main.py --fetch-tasks --wait-for-tasks 31536000 --task-poll-interval 1 --limit-tasks 100 --service-key-file Data/service-key.txt --upload-stats --client-id worker-transfer-01 --proxy-config Data/proxy.json --profile Data/browser-profiles/worker-transfer-01 --headed --captcha-key-file Data/key.txt --captcha-max-tasks 0 --captcha-kinds both --captcha-wait 900 --deadline 1800 --max-pages 5 --action-pause 15 --visit-seconds 100 --output sandbox/artifacts/worker-transfer-01
```

Замените `worker-transfer-01` на имя своего запуска (для новых логов используйте
новую папку output). Программа ждёт первый непустой пакет с паузой в секунду
после каждого ответа. Затем выполняет до 100 заданий из пакета, отправляет
допустимые результаты и завершается. Это один цикл, а не бесконечный worker.
Ожидание заданий ограничено годом; Ctrl+C останавливает процесс.

Текст и силуэты обрабатываются через CapGuru. `--captcha-max-tasks 0` снимает
лимит числа платных задач; каждая новая задача может оплачиваться. После явного
отказа распознавания или отсутствия ответа за 60 секунд после получения ID
программа нажимает «Обновить задание». Новый запрос отправляется только после
подтверждённой смены и загрузки картинки. Если кнопки нет или обновление не
подтверждено, задание завершается с диагностикой. Число таких повторов ограничено
общим тайм-аутом задания и явно заданной квотой, если она включена.
Опрос CapGuru идёт каждые 10 секунд; готовое решение применяется сразу.
Загрузка картинки и доступность элементов ожидаются в пределах общего тайм-аута,
не отправляя незагруженное изображение. Неизвестный
результат создания задачи после сетевой ошибки не повторяется. Неподдерживаемая
CAPTCHA или неисправимая ошибка завершают задание с диагностикой без ожидания
человека; worker освобождает прокси и продолжает цикл.
Ключ CapGuru обязателен в постоянном режиме. `--captcha-wait` теперь задаёт
только окно пассивного восстановления после HTTP 429 (максимум 120 секунд),
а не ожидание ручного решения. Число автоматических задач по умолчанию не ограничено.
Slider сохранён в legacy-коде; современный runner автоматически его не решает.
Общий тайм-аут каждого поискового задания — 30 минут, включая ожидания.
На найденном сайте программа ждёт 100 секунд перед завершением задания.

## Результаты

В папке output находятся `runner.log`, `received-tasks.json`, `results.jsonl`,
`captcha-service.json`, квитанция `submission-*.json` и подпапки с диагностикой.
Логи и снимки не отправляйте в публичный Git: они могут содержать данные сессии.
HTTP 200 в квитанции подтверждает HTTP-ответ; запись проверяется в таблице prstar.
Код выхода 0 — задания завершены; 1 — неполный поиск; 2 — ошибка пакета/ожидания.

### Если появляется `batch exit 2`

Откройте `console.log` указанного chunk и `batch-error-*.json`. Поле `stage`
показывает место сбоя: `browser_start` — запуск Chrome/профиля,
`run_task` — выполнение задания, `browser_close` — закрытие браузера,
`submit_stats` — отправка отчёта, `save_submission_receipt` — запись квитанции.
`error_type` — тип исключения, `message` — объяснение с удалёнными секретами,
`traceback` — последние файлы, функции и номера строк без значений переменных.
В подпапке отдельного задания есть `task-error.json`, если ошибка произошла
внутри поиска. Ошибки самого worker сохраняются как `worker-error-*.json`.
Ошибки параметров CLI находятся в `console.log` и могут не создавать JSON.

## Сборка архива

```sh
python sandbox/build_release.py
```

Архив и его SHA-256 появятся в `dist`. Ключи, профили, логи, виртуальное
окружение и старый бинарный ChromeDriver в сборку не включаются.
